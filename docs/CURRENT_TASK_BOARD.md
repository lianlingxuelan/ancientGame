## 给 Claude Code 的默认协作任务模板

如果 Codex 完成下一轮 T01-T03，请交给 Claude Code 做以下检查：

### BattleApiFE-R1-REV

目标：审查 Unity 战斗页接入后端战斗配置与技能图标后的稳定性。

需要检查：

1. `/api/v1/battle/demo-config` 字段变化是否会导致 Unity 空引用或空页面。
2. `/api/v1/assets?category=battle_skill` 返回缺图或空列表时，Unity 是否能回退到文字按钮。
3. 李清照、婉禾是否都进入战斗行动队列。
4. 技能按钮是否可点击，冷却/目标/行动点是否不会互相冲突。
5. 不允许通过删除 `shouyou.db` 作为默认修复方案。
6. 确认 JSON 响应头包含 `charset=utf-8`，或至少 Unity 侧 UTF-8 解析不乱码。
7. 确认旧 DB 编队数据与 demo-config 不一致时，Unity 只采用一个权威数据源，不出现 slot2 冲突。

验收标准：

1. Unity 可进入 Play Mode，无编译错误。
2. 庭院 → 主线 → 战斗页可进入。
3. 至少能看到两个我方角色、六个敌方单位、四个技能按钮。
4. 任意可用技能点击后能造成伤害或治疗，并刷新 UI。
5. 接口不可用时，战斗页仍显示本地 Demo，不崩溃。

## 当前风险

1. 文档中已有部分中文乱码，后续新文档必须使用 UTF-8 保存。
2. Unity 2020 对部分现代 C# 写法支持有限，代码应保持保守。
3. 当前战斗 UI 仍是 Demo 状态，不应过早追求最终美术。
4. 后端接口字段如果频繁变动，会导致前端反复返工；需要优先稳定 DTO。
5. 原始素材池图片很多，不应一次性导入或提交。
6. 旧 `shouyou.db` 里的编队数据可能是 slot2 无婉禾，而新接口数据 slot2 有婉禾；如果 Unity 同时读两处，会出现阵容和战斗初始化互相覆盖。
7. 后端 Node 读 JSON 中文正常，不代表 Unity 直接读一定正常；接口和客户端都要明确 UTF-8。
