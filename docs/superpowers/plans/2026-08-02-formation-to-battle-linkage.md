# 编队编辑与战斗入场联动实施计划

## 目标

让第一章主流程中的编队成为实际可编辑的数据源：玩家选槽位、选角色、保存后，战斗页按保存的六槽阵容生成我方单位。

## 本轮边界

- 只改 Unity 前端和静态验证脚本。
- 继续使用 `ShouyouBackendBootstrap` 已缓存、已保存的编队接口作为唯一阵容身份来源。
- 战斗 demo-config 只提供敌方与我方数值模板；不再覆盖已保存的我方角色身份。
- 不改后端、不删数据库、不改伤害或行动值公式、不引入梦域/养成/抽卡。

## 实施步骤

1. 扩展编队页，加入“选择角色”面板、两个候选角色按钮和清空当前槽位按钮。
2. 编队控制器改为“先选槽位、再点候选角色”模式，阻止重复上阵，并保留循环切换作为无候选面板时的降级交互。
3. 保存成功后以返回的后端缓存为准重新刷新编队页；保存失败则保留当前草稿并明确提示。
4. 战斗初始化读取该缓存的六槽角色身份；数值仍优先沿用已有 demo-config 的槽位模板，空位保持不可出战。
5. 新建静态契约验证，覆盖候选选择、重复防护、保存回刷、战斗身份读取；再跑既有战斗验证与数据库未改检查。

## 验收

1. 可在编队页点一个槽位，再点李清照或婉禾完成上阵；同一角色不会出现在两个槽位。
2. 点“保存编队”成功后，重新进编队页仍显示服务端返回的阵容。
3. 进入战斗后，我方头像名称与已保存的槽位一致；空位不进入行动队列。
4. 未改动 `ShouyouServer/data/shouyou.db`。
